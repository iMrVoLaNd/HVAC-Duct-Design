# Кнопка pyRevit: шаблон вида с фильтрами систем вентиляции

Вкладка **HVAC** → панель **Systems** → кнопка **«Шаблон систем»** (Revit 2026, pyRevit).

## Что делает кнопка

1. Берёт **активный вид** (план, разрез, фасад, 3D) и создаёт из него **шаблон вида** (`View.CreateViewTemplate`).
2. Для **каждой системы отдельно** (П1…П20 и В1…В20) создаёт **фильтр** `ОВ_П1`, `ОВ_В12`… с правилом
   **`ADSK_Система_Имя` равно «П1»** (точное совпадение: `П1` не захватывает `П10`).
3. Фильтры действуют на **категории вентиляции**: воздуховоды, гибкие воздуховоды, соединительные детали, арматуру,
   воздухораспределители, изоляцию, внутреннюю изоляцию, заменители воздуховодов (список `CATEGORIES` в `script.py`;
   категории, к которым параметр не привязан, пропускаются автоматически и показываются в отчёте).
4. Добавляет фильтры в шаблон, включает их видимость и задаёт **графику**: заливка поверхности (Solid fill) цветом системы
   из палитры сайта, линии стенок — выбранного цвета и толщины (и на виде, и в разрезе).
5. Предлагает применить шаблон к активному виду.

В диалогах выбираются: имя шаблона, какие системы (все / только П / только В), **цвет линий стенок**
(чистые, сигнальные, спокойные, приглушённые, тёмные, чёрные, серые — как на сайте) и **толщина**
(тонкие / средние / толстые → 1 / 2 / 4 в Revit).

Повторный запуск не плодит дубликаты: существующие фильтры обновляются, а если шаблон с таким именем уже есть, можно
обновить его или создать новый (`_2`).

## Вторая кнопка: QuickFlexConnect

Вкладка **HVAC** → панель **Systems** → **QuickFlexConnect** (раньше называлась «Гнучкий між конекторами»; папка команды — `101_QuickFlexConnect.pushbutton`). Имя секции конфигурации pyRevit осталось прежним (`flex_between`), чтобы не потерять сохранённые настройки.

1. Сначала **выберите два элемента** (см. ниже), и только потом кнопка спрашивает тип и размер — уже зная, что вы соединяете:
   - **размеры одинаковые** (допуск 0,5 мм): окно только с типом (одним выпадающим списком, последний выбранный уже
     подставлен, **Enter** — подтвердить, **Esc** — отменить). В режиме «Цикл» тип запоминается на серию и не спрашивается,
     пока подходит по форме; если тип в проекте один — окна нет вообще;
   - **размеры или форма разные**: одно окно с двумя **чипами** — размер первого и размер второго элемента (по умолчанию
     выбран первый, Enter сразу подтверждает), под ними выпадающий список **«Другой размер…»** со стандартными круглыми
     диаметрами из «Механических настроек» проекта; для **прямоугольных и овальных** сечений вместо него два списка
     **«Ширина…» и «Высота…»** со стандартными размерами проекта (то, что не выбрано, остаётся как у выбранной плашки;
     если стандартные размеры не прочитались — остаются только плашки), и список **типа**; он сам подстраивается под форму
     выбранного размера (круглый / прямоугольный / овальный);
   - поддерживаются **круглые, прямоугольные и овальные** сечения: круглые получают диаметр, прямоугольные и овальные —
     ширину и высоту. Форма типа берётся из `Shape` типа гибкого воздуховода; если Revit её не отдаёт, тип не фильтруется;
   - если для формы нет подходящего типа, кнопка так и скажет и ничего не построит.
   - **Тип с образца в модели** (включается галочкой в настройках, по умолчанию выкл.): вместо выпадающего списка кнопка
     просит **кликнуть на любой гибкий воздуховод** в модели («Esc» — выбрать из списка) и берёт тип с него. Кликнуть можно
     только на гибкий воздуховод. Если тип образца не подходит по форме, кнопка предупредит и покажет список. Если размеры
     элементов **разные**, образец не спрашивается: сразу открывается окно с чипами размеров и типом (оно само по себе выбор).
     В цикле образец спрашивается один раз.
   **Настройки** — в окне по **Shift+клик** на кнопке: галочка **«Тип гнучкого — з повітровода в моделі»**, параметр
   **«Гибкая конфигурация»**
   (`BuiltInParameter.RBS_FLEX_PATTERN_PARAM` — находится независимо от языка Revit) и галочка **«Цикл»**
   (по умолчанию **выключена**). Значение параметра выбирается **только из выпадающего списка его вариантов**
   (своё вписать нельзя), по умолчанию — **«Гибкий»**; первый пункт списка «(не змінювати параметр)» = не трогать параметр. Варианты окно читает из проекта: берёт первый гибкий воздуховод (или тип),
   в транзакции, которая **откатывается**, перебирает значения параметра и запоминает их тексты — проект не меняется.
   Если гибких воздуховодов/типов с параметром в проекте нет, варианты прочитать не из чего — в списке остаются
   «(не змінювати параметр)» и сохранённое значение («Гибкий»); создайте один гибкий воздуховод и откройте настройки снова.
   Значение записывается после построения каждого гибкого воздуховода: сначала у самого воздуховода (экземпляр),
   потом у его типа. Если параметра нет или значение не принято, воздуховод всё равно построится, а появится окно с замечанием
   предупреждение; в журнал пишется список реальных имён параметров (учтите: параметр типа меняется для **всех**
   воздуховодов этого типа).
2. Кликните на первом элементе (выбирается **целый элемент**, точка на нём не показывается) **рядом с нужным коннектором**: берётся **свободный коннектор, ближайший к месту клика**
   (на арматуре с несколькими врезками — та врезка, у которой кликнули; у воздуховода — тот конец). Можно выбирать только
   **воздуховоды, арматуру воздуховодов, соединительные детали воздуховодов, оборудование и воздухораспределители**
   (список — `ALLOWED_CATEGORIES` в начале `script.py`). Элемент должен иметь вентиляционные коннекторы; если все они уже
   подключены, кнопка **сразу после первого клика** сообщит об этом (второй элемент выбирать не придётся) и запишет детали коннекторов в журнал. Если элемент не выбирается совсем, причина
   (категория, тип, домен и состояние его коннекторов) пишется в журнал строкой «елемент відхилено фільтром».
3. Так же кликните на втором элементе. Если точку клика получить не удалось, берётся **самая близкая пара свободных
   коннекторов**. Подсказки (шаг «1/2», «2/2», что уже выбрано, Esc) выводятся в **строку состояния Revit**. Между коннекторами строится гибкий воздуховод: две точки +
   касательные по направлению коннекторов (в Revit 2025+; в более старых версиях API — четыре точки, которые дают такой же
   выход по нормали). Концы **соединяются** с обоими коннекторами; размер — тот, что выбран (при одинаковых элементах — их общий).
4. С выключенным циклом (по умолчанию) строится **одна** пара, и кнопка завершается (**Esc** — отмена). С включённым —
   можно указывать пару за парой, **Esc** — завершить.

Тип системы берётся из системы, к которой уже подключён коннектор; если ни у одного коннектора системы нет — кнопка один раз
спросит тип. Уровень берётся от элемента, затем от активного вида, затем ближайший по высоте. Каждая пара — отдельная
транзакция (отмена Ctrl+Z убирает один воздуховод).

## Третья кнопка: FlexTail

Вкладка **HVAC** → панель **Systems** → **FlexTail** (папка `102_FlexTail.pushbutton`). Заменяет **часть жёсткого воздуховода
гибким** — на длину, которую вы укажете, считая от выбранного элемента (типичный случай: гибкая вставка у оборудования).

**Как работает**
1. Кнопка просит в строке состояния кликнуть по элементу: **оборудование, арматура воздуховодов, соединительная деталь
   или воздухораспределитель**. Берётся **ближайший к клику коннектор** (элемент может стоять посреди сети — по нему
   определяется, в какую сторону преобразовывать).
2. К этому коннектору **обязательно должен быть подключён жёсткий воздуховод**. Нет — появляется сообщение с причиной
   (ничего не подключено / подключён гибкий или другой элемент / воздуховод на другом коннекторе этого элемента), и кнопка
   снова просит кликнуть; Esc — выход.
3. Открывается окно. Вверху блок **«Найден элемент категории «Воздуховоды»»** с данными найденного воздуховода: **тип,
   сечение (Ø или ширина × высота) и длина**. Ниже **длина гибкого участка** (мм; по умолчанию 500, **последнее значение
   запоминается**; быстрые значения-кнопки 300, 500, 1000, 1500, 2000, 2500) и **тип гибкого воздуховода** (только
   подходящей формы: круглый / прямоугольный / овальный; последний выбранный подставлен). Под значениями-кнопками
   строка **«Будет создан гибкий воздуховод Ø200 мм длиной 500 мм. Останется воздуховод длиной 1500 мм.»** — она
   меняется вместе с введённой длиной, так что видно, что именно получится.
4. Воздуховод **режется** на заданном расстоянии от элемента (`MechanicalUtils.BreakCurve`), ближний кусок **удаляется**,
   на его месте строится **гибкий воздуховод того же сечения** (система, уровень берутся с воздуховода), концы
   подключаются к элементу и к оставшемуся жёсткому куску. Всё одной транзакцией: ошибка — откат.
5. «Гибкая конфигурация» записывается в созданный гибкий воздуховод — значение берётся из **настроек самой кнопки FlexTail**.

**Настройки FlexTail** (Shift+клик по кнопке) — своё окно и своя секция конфигурации pyRevit (`flex_tail`), не связанная с
другими кнопками, даже там, где функции повторяются: значение параметра «Гибкая конфигурация» (список из проекта,
по умолчанию «Гибкий»), **длина по умолчанию** (мм) и галочка **«Запоминать последнюю введённую длину»** (по умолчанию
включена; выключена — в окне всегда длина по умолчанию).

**Граничные случаи**
- Введена длина **больше длины найденного воздуховода**: окно сообщает «Максимально возможная длина — N мм», подставляет
  её в поле и остаётся открытым (второй OK — подтверждение; воздуховод преобразуется целиком). Подставленный максимум
  **не запоминается** как «последняя длина»; если запомненная прежде длина больше воздуховода, окно сразу показывает
  максимум (без сообщения и тоже без запоминания). Быстрые значения-кнопки длиннее воздуховода недоступны.
  Если после разреза остался бы жёсткий кусок короче 1/10 дюйма (Revit такой не строит), воздуховод тоже преобразуется
  целиком, с сообщением.
- Длина введена неверно (пусто, меньше 5 мм) — окно остаётся открытым и объясняет формат.
- Преобразуется только воздуховод, подключённый к ближайшему к клику коннектору; дальше (за фасонными деталями) кнопка
  не идёт.
- Если за дальним концом воздуховода нет никакого элемента, он всё равно преобразуется (подключение к несуществующему
  соседу пропускается). Раньше здесь Revit отвечал «The referenced object is not valid»: `Connector.AllRefs` отдаёт и
  логический коннектор системы, который исчезает вместе с удалённым воздуховодом, — теперь учитываются только настоящие
  соединения.
- Esc на выборе — тихий выход; закрытие окна — отмена без изменений. Окно вывода pyRevit не используется; окна сообщений появляются, только когда есть
  о чём сообщить. Шаги и ошибки пишутся в тот же журнал, что и у других кнопок.

**Не проверено в живом Revit:** что именно возвращает `MechanicalUtils.BreakCurve` и остаются ли после разреза куски
подключёнными к остальной сети — код определяет ближний и дальний кусок по геометрии, а не по порядку.

## Общий вид окон

Окна всех кнопок (выбор типа, размер и тип, настройки, FlexTail) собираются модулем `lib/hvac_ui.py` в одном стиле — как
на слайдах презентации: тёмно-синяя шапка, светлое тело, поля и списки с рамкой и скруглением, плашки-чипы, основная
кнопка (OK / Сохранить, срабатывает по Enter) залита тёмно-синим, «Отмена» (Esc) — с рамкой. В окнах выбора QuickFlexConnect
сверху показан блок **«Выбранные элементы»**: у каждого элемента категория, тип и сечение его коннектора (если размеры
одинаковые — ещё и размер будущего гибкого воздуховода). Не удалось создать окно — кнопки переходят на стандартные
диалоги pyRevit.

## Вызов с клавиатуры, как у кнопок ленты

Команду можно вызывать двумя буквами, как встроенные команды Revit: **Вид → Интерфейс пользователя → Сочетания клавиш**
(View → User Interface → Keyboard Shortcuts), в поиске введите `Quick`, выберите **QuickFlexConnect** и задайте
сочетание, например **QF** (проверьте, что оно не занято). Дальше достаточно набрать две буквы на клавиатуре, без Enter.
Если команды нет в списке — перезапустите Revit: список команд pyRevit читается при запуске, а не при Reload.
Сочетания хранятся в файле `%APPDATA%\Autodesk\Revit\Autodesk Revit 2026\KeyboardShortcuts.xml` — его можно экспортировать
в окне сочетаний и передать коллегам. Каждое расширение/кнопка pyRevit получает такую команду автоматически, отдельной
настройки в коде не требуется.

## Установка: копируйте папку целиком

Кнопки используют общую папку **`HVAC.extension/lib`** (там `hvac_log.py`, `hvac_revit.py`, `hvac_flex_settings.py`, `hvac_palette.py`,
`palette.json`). Копируйте/синхронизируйте **всё `HVAC.extension` целиком**, а не отдельные папки кнопок. Если в окне ошибки
написано `No module named 'hvac_...'` — какого-то файла из `lib` нет (часто это недосинхронизированный Google Drive): дождитесь
синхронизации, проверьте, что все файлы на месте, и сделайте **Reload** в pyRevit. Кнопка в таком случае сама покажет,
какого файла не хватает и где она его искала.

## Скорость

- При успешном построении **никаких окон** (результат — в журнале); окно появляется только при предупреждении или ошибке.
- Значение «Гибкая конфигурация» записывается быстро: число варианта запоминается (при сохранении настроек или при первом
  построении), и дальше это один быстрый вызов вместо перебора значений с перерасчётом модели. Если число устарело
  (другая версия/язык Revit), кнопка сама найдёт и запомнит новое.
- Фильтр выбора считает список категорий один раз, а результат для каждого элемента **кешируется**: при движении курсора
  над элементом коннекторы повторно не читаются; тип элемента определяется по классу Revit (`MEPCurve` / `FamilyInstance`),
  без дорогих исключений.
- Значение «Гибкая конфигурация» пишется **без перерасчёта модели**: запомненное число доверяется только в той же версии и
  языке Revit, а результат проверяется одним чтением после транзакции (при расхождении — один раз исправляется и запоминается заново).
- Модули `uuid`, `tempfile` и `traceback` не импортируются на обычном пути, `pyrevit.forms` (WPF) загружается только когда
  нужно окно, конфигурация pyRevit читается один раз за запуск, журнал пишется одним открытием файла.
- В журнале видно, где уходит время: «підготовка до першого вибору … мс», «створено, id …, … мс» (построение) и «=== кінець, … мс»
  (весь запуск, включая время ваших кликов и окон). Если что-то кажется медленным — пришлите эти строки.

## Журнал: если кнопка падает

У каждой кнопки **свой журнал в её собственной папке** (рядом со скриптом): `101_QuickFlexConnect.pushbutton\QuickFlexConnect.log`,
`102_FlexTail.pushbutton\FlexTail.log`, `103_SystemsTemplate.pushbutton\SystemsTemplate.log`. Если в папку писать нельзя (например,
она только для чтения), журнал уходит в `%APPDATA%\HVAC-Duct-Design\<кнопка>.log`.
Что в нём: какой движок Python и версия Revit, какие элементы выбраны, какая пара коннекторов, какой вариант
`FlexDuct.Create` сработал, а при ошибке — **полный traceback** (с пометкой `ПОМИЛКА`) и откат транзакции.
При ошибке кнопка показывает окно с traceback (кнопки «Копировать» и «Открыть журнал»). Esc не считается ошибкой.
Если кнопка не запускается совсем, в журнале будет запись об ошибке импорта. Файл не растёт бесконечно (при 512 КБ
старый уходит в `<кнопка>.log.1`). Для сообщения об ошибке достаточно прислать последние ~40 строк журнала.

## Установка

**Быстро — готовый архив:** [HVAC.extension.zip](https://github.com/iMrVoLaNd/HVAC-Duct-Design/raw/main/dist/HVAC.extension.zip)
(скачивается сразу, без входа в GitHub; внутри — папка `HVAC.extension` и файл `УСТАНОВКА.txt`).

1. Установите актуальный pyRevit с поддержкой Revit 2026.
2. Распакуйте архив в постоянную папку, например `C:\pyRevit\HVAC` (внутри должна лежать папка `HVAC.extension`).
3. pyRevit → **Settings → Custom Extension Directories → Add** → выберите папку, **в которой лежит** `HVAC.extension`
   (в примере — `C:\pyRevit\HVAC`) → **Save Settings and Reload**.
4. На ленте появится вкладка **HVAC**.

Презентации (PDF): [QuickFlexConnect](https://github.com/iMrVoLaNd/HVAC-Duct-Design/raw/main/dist/QuickFlexConnect-slides.pdf),
[FlexTail](https://github.com/iMrVoLaNd/HVAC-Duct-Design/raw/main/dist/FlexTail-slides.pdf).

Из репозитория: в шаге 3 выберите папку **`pyrevit`** (ту, внутри которой лежит `HVAC.extension`).

Архив собирается командой `python3 tools/build_plugin_zip.py` (результат — `dist/HVAC.extension.zip`); тест
`test_dist.py` следит, чтобы архив в репозитории всегда совпадал с кодом. Журналы, `settings.ini` и кэш Python в архив не попадают.
При обновлении плагина распакуйте новый архив поверх старого: ваши `settings.ini` и журналы останутся на месте.

## Номера в именах папок кнопок

Папки кнопок начинаются с номера `1##`: `101_QuickFlexConnect`, `102_FlexTail`, `103_SystemsTemplate`. По номеру задаётся
положение кнопки на панели (порядок по возрастанию) и «адрес» кнопки. Новую кнопку добавляйте со следующим номером (`104_…`).
Номер — только в имени папки: заголовок на ленте, имя журнала (`FlexTail.log`) и текст в `settings.ini` от него не зависят.
После переименования Revit видит команды заново: **сочетания клавиш, назначенные на старые имена, нужно назначить ещё раз**.

## Настройки кнопок

У каждой кнопки **свой файл настроек** `settings.ini` в её папке (`102_FlexTail.pushbutton\settings.ini`,
`101_QuickFlexConnect.pushbutton\settings.ini`). Это обычный текст `ключ = значение`: можно открыть в блокноте; удалите файл —
вернутся значения по умолчанию. Окно настроек у каждой кнопки тоже своё (Shift+клик по кнопке). Настройки, которые раньше
хранились в конфигурации pyRevit, при первом запуске один раз переносятся в новый файл.

## Окна

Окна кнопок без системной рамки, но их можно **перетаскивать мышью** за шапку и за любое пустое место окна.

**Поля ввода защищены от неверных данных.** В числовые поля (длина) нельзя ввести и вставить ничего, кроме цифр и одного
разделителя (запятая или точка): буквы, пробелы, минус и «мм» стираются сразу; не больше 5 цифр до разделителя и одной
после. В каждом поле справа есть кнопка **«×»** — очистить поле. Остальные окна состоят только из списков, кнопок и флажков
(значение можно только выбрать). В кнопке SystemsTemplate название шаблона не принимается пустым, слишком длинным или с
символами, которые Revit запрещает в именах (`\ : { } [ ] | ; < > ? ~` и обратный апостроф).

**Сообщения, предупреждения и ошибки** показываются в таком же окне (`lib/hvac_dialog.py`), а не в стандартных диалогах
pyRevit и не в окне вывода. Цветная метка показывает вид: «Информация», «Внимание», «Ошибка». В окне:
- **элементы со ссылками**: если в сообщении упомянуты элементы, каждый — строка «Категория «Тип» · id 123456»; клик по ней
  **выделяет элемент в модели и показывает его** на виде (после клика внизу окна — пояснение, получилось ли);
- **«Копировать»** — весь текст сообщения (с подробностями ошибки, списком элементов и путём журнала) в буфер обмена;
- **«Открыть журнал»** — файл журнала этой кнопки (у ошибок кнопка есть всегда);
- у ошибки в поле **«Подробности»** — traceback; текст в нём выделяется и копируется;
- замечания после работы (например, «Гибкая конфигурация» не принята параметром) собраны в одном окне «Построено/Преобразовано,
  но есть замечания»; окно вывода pyRevit больше не открывается. Отчёт SystemsTemplate тоже в этом окне, с вопросом
  «Застосувати шаблон?».
Не получилось создать окно — показывается стандартный диалог с тем же текстом. Enter и Esc закрывают окно, оно перетаскивается.

**Блок «Выбранные элементы»** (QuickFlexConnect): каждый элемент — две строки (категория и сечение; ниже тип в кавычках),
чтобы длинное имя типа не переносилось посреди строки. В конце — что будет создано: «Будет создан гибкий воздуховод
Ø125 мм, длиной около 850 мм» (длина — по прямой между выбранными коннекторами; если размеры разные, размер выбирается
ниже в этом же окне).

## Что нужно в проекте

Параметр **`ADSK_Система_Имя`** (общий параметр из файла ADSK) должен быть в проекте и привязан к категориям вентиляции,
а у элементов — заполнен значениями `П1`, `В1`… **кириллицей** (`П` U+041F, `В` U+0412 — как на сайте).
Если параметра нет или он ни к одной категории не привязан, кнопка сообщит об этом и ничего не изменит.

## Цвета берутся с сайта

Цвета и варианты стенок хранятся в `HVAC.extension/lib/palette.json`. Файл **генерируется** из `js/palette.js` сайта,
чтобы источник был один:

    node tools/export-palette-json.js

Запускайте после любого изменения палитры на сайте.

## Проверка без Revit

    python3 -m unittest discover -s pyrevit/tests -v

Тесты проверяют логику палитры (в том числе что `palette.json` совпадает с сайтом) и делают «сухой прогон» кнопки на
заглушках API Revit: число фильтров, правило `ADSK_Система_Имя = П1`, категории, цвета, повторный запуск, отказ при
отсутствии параметра. **Это не замена проверке в настоящем Revit 2026**: заглушки повторяют только те вызовы API, которые
использует скрипт. Скрипт написан без f-строк и современного синтаксиса, чтобы работать в IronPython 3.4 (pyRevit).
