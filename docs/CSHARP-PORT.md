# Перенос QuickFlexConnect и FlexTail на C# — план и спецификация

Цель: два плагина, которые сейчас работают как кнопки pyRevit (IronPython 3.4, `pyrevit/HVAC.extension/`), переписать как
**обычное дополнение Revit на C#** (без pyRevit). **Эталон поведения — сам Python-код и его тесты**: они показывают, что именно
должно получиться. Владелец — начинающий C#-программист: объясняйте шаги, держите код простым, коммитьте небольшими кусками.

## 0. Сначала согласуйте с владельцем (не решайте молча)
1. Версии Revit: сейчас только **Revit 2026 (.NET 8)**. Нужны ли 2024/2025? (У 2024 и ниже — .NET Framework 4.8; `ElementId` — int, с 2024 — long.)
2. Оставляем ли pyRevit-версию рядом (как эталон/запасной вариант)? Рекомендуется: да, пока C# не принят.
3. Куда складывать C#: рекомендуемо новая папка `csharp/` в этом репозитории, решение `HvacTools.sln`.
4. Установка: `.addin` + папка в `%ProgramData%\Autodesk\Revit\Addins\2026\` (или `%AppData%\Autodesk\Revit\Addins\2026\`) и zip в `dist/`.
5. Имя вкладки/панели на ленте: сейчас вкладка **HVAC**, панель **Systems**; кнопки в порядке 101, 102 (номера из имён папок задают порядок).

## 1. Рекомендуемая структура решения
```
csharp/
  HvacTools.sln
  src/HvacTools.Core/     чистая логика без Revit (размеры, длина, настройки, журнал, разбор чисел) — .NET 8, тестируется xUnit
  src/HvacTools.Ui/       WPF: общий стиль (ResourceDictionary), окна: выбор размера/типа, длина/тип, настройки, сообщение
  src/HvacTools.Revit/    обёртки над Revit API (коннекторы, создание гибкого, разрез, параметры, выделение)
  src/HvacTools.Addin/    IExternalApplication (лента) + IExternalCommand для каждой кнопки, .addin, иконки
  tests/HvacTools.Core.Tests/   порт логики из pyrevit/tests (xUnit)
```
Ссылки на `RevitAPI.dll`/`RevitAPIUI.dll` — только в `Revit` и `Addin`, с `Private=false` (не копировать).
`Core` и его тесты запускаются в облаке без Revit (`dotnet test`); всё, что трогает Revit, — только на машине владельца.

## 3. Поведение QuickFlexConnect (подробно — `pyrevit/README.md`, раздел «Первая кнопка», и `docs/QuickFlexConnect-TZ.md`)
- Два клика `PickObject` с `ISelectionFilter`: категории `OST_DuctCurves`, `OST_DuctAccessory`, `OST_DuctFitting`,
  `OST_MechanicalEquipment`, `OST_DuctTerminal`, у элемента должны быть вентиляционные коннекторы (`Domain.DomainHvac`).
  Выбирается целый элемент; берётся **свободный коннектор, ближайший к точке клика** (`Reference.GlobalPoint`); нет точки — ближайшая пара.
- Подсказки в строке состояния («1/2 …», «2/2 — первый: Воздуховоды Ø200 …», «3/3 — образец…», в цикле «пара N: …»).
- Если у **первого** элемента нет свободных коннекторов — сообщение сразу после первого клика (второй не запрашивается);
  у второго — после второго. «Один и тот же элемент» — сообщение. Режим «Цикл»: после сообщения/постройки снова первый клик; Esc — выход.
- Размер: форма и размер читаются с коннектора (`Connector.Shape`, `Radius`/`Width`/`Height`). Одинаковые (допуск 0,5 мм) — окна размера нет,
  только выбор типа; разные — окно «Размеры элементов разные»: плашки «1-й/2-й», список «Другой размер…» (круглые — стандартные диаметры
  `DuctSizeSettings`), для прямоугольных/овальных — два списка «Ширина…» и «Высота…» (стандартные размеры проекта), список типов
  гибкого по форме. Один подходящий тип в проекте — окон нет. «Тип с образца» (настройка) — клик по готовому гибкому, тип берётся с него.
- Построение: `FlexDuct.Create` — вариант с касательными (Revit 2025+: две точки + направления), запасной — 4 точки; тип системы — от
  системы коннектора (`Connector.MEPSystem`), иначе выбор; уровень — от владельца коннектора → уровень вида → ближайший по высоте.
  Размер задаётся параметрами `RBS_CURVE_DIAMETER_PARAM` / `…WIDTH…` / `…HEIGHT…`; концы подключаются `ConnectTo` к ближайшим коннекторам.
  Меньше 1/10 дюйма между коннекторами — ошибка «слишком близко». Всё в одной транзакции, ошибка → откат.
- Параметр «Гибкая конфигурация» (`RBS_FLEX_PATTERN_PARAM`, список): значения читаются перебором целых чисел с откатом транзакции, число
  варианта запоминается вместе с контекстом (версия Revit + язык), дальше значение пишется быстро одним вызовом; значение по умолчанию «Гибкий»;
  нет параметра/значение не принято — воздуховод строится, показывается окно замечаний.
- Окно сообщений «Построено, но есть замечания». Блок «Выбранные элементы» в окнах: по две строки на элемент (категория и сечение; ниже тип),
  затем «Будет создан гибкий воздуховод / Ø125 мм, длиной около N мм» (расстояние по прямой между коннекторами).

## 4. Поведение FlexTail (`pyrevit/README.md`, «Третья кнопка»)
- Клик по оборудованию/арматуре/фасонной детали/воздухораспределителю → ближайший к клику коннектор → к нему должен быть подключён **жёсткий
  воздуховод** (иначе окно с причиной и повторный запрос; причины: нет вентиляционных коннекторов / подключён гибкий или другой элемент /
  воздуховод на другом коннекторе этого элемента).
- **Важно (баг, уже исправлен в Python):** `Connector.AllRefs` отдаёт и *логические* коннекторы системы, они исчезают вместе с удалённым
  воздуховодом → «The referenced object is not valid». Брать только физические (`ConnectorType.End/Physical`) и пропускать недействительные цели.
- Окно «Длина и тип»: блок «Найден элемент категории «Воздуховоды»» (тип, сечение, длина), поле длины (по умолчанию 500 мм, запоминается,
  чипы 300/500/1000/1500/2000/2500), строка «Будет создан гибкий воздуховод Ø200 мм длиной 500 мм. Останется воздуховод длиной 1500 мм.»,
  тип гибкого (по форме). **Длина больше воздуховода:** сообщение «Максимально возможная длина — N мм», в поле подставляется максимум, окно
  остаётся открытым, подставленное **не запоминается**; чипы длиннее воздуховода недоступны; запомненная длина больше воздуховода — сразу максимум.
- Преобразование: `MechanicalUtils.BreakCurve(doc, ductId, точка)` на заданной длине от элемента, ближний кусок удаляется, на его месте
  `FlexDuct.Create` того же сечения (система и уровень от воздуховода), концы подключаются к элементу и оставшемуся жёсткому куску.
  Короче/равно длине или остаток < 1/10 дюйма — преобразуется целиком (сообщение при «остаток слишком мал»). За дальним концом пусто — пропустить подключение.
  Допуск равенства длин — 1 мм. Одна транзакция.
- **Не проверено в живом Revit** (проверить первым делом в C#): что именно возвращает `BreakCurve` и какие куски остаются подключёнными (код
  определяет ближний/дальний кусок по геометрии, а не по порядку); чтение стандартных размеров `DuctSizeSettings` для прямоугольных/овальных.

## 5. Общие требования к интерфейсу (все окна)
Русский язык; стиль — как `lib/hvac_ui.py` (цвета, шрифты, скругления); без системной рамки (`WindowStyle=None`), перетаскивание за любое пустое
место; Enter/Esc; `Topmost`; окно владельцем — главное окно Revit (`WindowInteropHelper`). Числовые поля принимают только цифры и один разделитель
(≤5 цифр до и 1 после), кнопка «×» очищает. **Окон вывода нет**: сообщения/ошибки — `MessageWindow` (метка «Информация/Внимание/Ошибка»,
ссылки на элементы по id — клик **только выделяет** элемент: без приближения вида, подсказок и сообщений об успехе; «Копировать»; «Открыть журнал»;
подробности ошибки в выделяемом поле). Тексты окон должны совпадать со слайдами (`slides/README.md`). Окно настроек у каждой кнопки своё
(Shift+клик в pyRevit; в C# — отдельная кнопка/пункт, согласовать с владельцем).

## 6. Настройки и журнал
Файлы лежат **в папке плагина** (рядом с .dll): `<Плагин>.log` и `settings.ini` у каждой кнопки свои. Формат `settings.ini`: комментарий `#`,
`[settings]`, `ключ = значение` (подробнее — `lib/hvac_settings.py`); ключи: `config_value`, `config_value_num`, `config_value_ctx`, `loop`,
`type_from_model`, `flex_type`, `system_type` (QuickFlexConnect); `config_value*`, `length_mm`, `default_length_mm`, `remember_length`, `flex_type` (FlexTail).
Нельзя писать в папку (Program Files) — запасной путь `%APPDATA%\HVAC-Duct-Design\`. Из pyRevit-настроек значения переносились один раз (в C# не нужно).

## 7. Тесты
Каждый файл в `pyrevit/tests/` — каталог сценариев: `test_sizes.py`, `test_tail_logic.py`, `test_settings.py`, `test_log.py`, `test_ui.py`
(разбор чисел), `test_dialog.py` → портировать в xUnit для `Core` (и логики окон, которая не требует WPF); `test_flex_button.py` и
`test_flex_tail.py` — длинные сценарии на заглушках Revit: читать как список поведений и проверять руками в Revit по чек-листу (ниже).
Правило: новое поведение — с тестом в `Core`; всё, что нельзя проверить без Revit, — честно в список «не проверено».

## 8. Чек-лист приёмки в Revit (для владельца, по каждой кнопке)
QuickFlexConnect: два воздуховода одного диаметра; разные диаметры (плашки и «Другой размер…»); прямоугольные (ширина/высота); овальные;
оборудование + воздуховод; первый элемент без свободных коннекторов (сообщение сразу); «Тип с образца»; «Цикл»; план, 3D-вид, разрез;
параметр «Гибкая конфигурация» (есть/нет/не принято); отмена Esc на каждом шаге; Ctrl+Z одним шагом.
FlexTail: клик по оборудованию, по арматуре, по тройнику посреди сети (направление по месту клика); длина короче/длиннее/равна воздуховоду;
пусто за дальним концом; подключён гибкий (отказ); округлый/прямоугольный; длина запоминается, подставленный максимум — нет.
Общее: окна двигаются; «×»; ссылка на элемент выделяет его; «Копировать»; «Открыть журнал»; ошибка показывает окно с подробностями.

## 9. Порядок работы (предложение)
1. Каркас: решение, `Core` + тест-проект, лента и пустые команды, `.addin`; запуск в Revit (отладка: Visual Studio → Attach to Process Revit.exe).
2. `Core`: порт `Sizes`, `TailLogic`, `IniSettings`, `Logger` с тестами.
3. `Ui`: стили, `MessageWindow`, числовое поле.
4. **FlexTail** (проще: один клик) → проверка в Revit → **QuickFlexConnect** → проверка.
5. Слайды: поправить то, что отличается; пересобрать PDF (`slides/README.md`).
6. Установка: zip в `dist/` и инструкция.
